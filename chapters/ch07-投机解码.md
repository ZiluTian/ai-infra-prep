## 7.1 原理与数学

目标模型一步 decode = 一次全量 HBM 权重读取(Ch1)。核心问题:**能否一次读取产出多于 1 个 token?**

投机解码:先用 draft(便宜)猜 γ 个 token,目标模型用**一次并行 forward** 验证这 γ 个 token(tree attention),接受最长合法前缀:

```
目标模型独自: [1 token/步]  [1 token/步]  [1 token/步]
投机解码:    draft:  d1 d2 d3 d4 d5(廉价小模型若干步)
            target: 一次 forward 验证 d1..d5 → 接受 d1 d2,拒绝 d3
            → 一轮产出 3 token(2 接受 + 1 个目标模型的"纠正 token")
```

**数学(Leviathan et al. 2023)**:

- α = 逐 token 接受率。接受是几何过程:第 k 位有效要求前 k−1 位全部被接受 → P(第 k 位被接受) = α^k,一轮期望接受数 **L = α(1−α^γ)/(1−α)**(几何级数求和),另加 1 个纠正 token
- 一轮成本 = 草稿 γ×c_d + 目标验证 1(c_d = draft 单步成本 / 目标单步成本)
- **净加速 = (1 + L) / (1 + γ·c_d)**;速算式 (1+γα)/(1+γ·c_d) 是其**上限**(忽略几何衰减,高估)

例:γ=5、α=0.8、c_d=0.1(draft 是 1/10 规模)→ L = 0.8×(1−0.8⁵)/(1−0.8) ≈ 2.69,一轮 3.69 token ÷ 成本 1.5 ≈ **2.5×**(上限式 3.3×);
同 α 但 c_d=0.5(draft 太大)→ 3.69/3.5 ≈ **1.1×**(上限式 1.4×)。**"投机解码不快"多半是 draft 选型问题,不是原理问题。**

**为什么无损(rejection sampling,证明梗概)**:

- draft 分布 q(x),目标分布 p(x)。逐 token:以概率 min(1, p/q) 接受草稿 token;否则从归一化的 max(0, p−q) 重采样
- 引理:该过程输出的单 token 分布严格等于 p;token 间串行验证保持联合分布 = 目标模型的自回归分布
- 实现:目标模型一次 forward 得到 γ 个位置的概率 + 1 个"纠正位置";一次采样完成"接受前缀 + 纠正 token"

```python
# speculative sampling 核心(简化自 Leviathan et al.;框架实现为融合 kernel)
# q: draft 概率 (γ, V);p: 目标概率 (γ+1, V),最后一行是"纠正位置"分布
def speculative_sample(q, p):
    r = torch.rand(γ, 1)                       # 均匀随机数
    accept = (r < p[:, :-1] / q).cumprod(-1)   # 任一位置拒绝 → 其后全部作废
    n_accept = int(accept.sum())
    bonus = sample_from(F.relu(p[n_accept] - q[n_accept]))  # 纠正 token: norm(p - q)
    return draft_tokens[:n_accept] + [bonus]
```

> 注意:被接受的 token 虽然"来自 draft",但经过 rejection 过滤后其分布就是 p——**草稿只贡献了候选,不贡献分布**,这是"无损"的全部秘密。

## 7.2 Draft 来源谱系

| 方法 | draft 机制 | 需训练 | α 特征 | 适用 |
|---|---|---|---|---|
| draft 模型(Leviathan) | 同家族小模型 | 否(现成小模型) | 中 | 通用、最快落地 |
| Medusa | 目标模型上加多头预测未来 k 个 token | 是(微调头) | 高(同模型) | 模型固定 |
| EAGLE | 特征级自回归(在 hidden state 上 autoregress) | 是(轻量头,训练快) | 很高(0.8+) | 生产首选 |
| EAGLE-2/3 | 免训练动态树 / 多层特征 | 部分免训 | 高 | 快速上线 |
| n-gram(vLLM 内置 `method:ngram`;TRT-LLM n-gram spec / llama.cpp ngram-simple) | 从上下文自身取候选(重复/检索) | 否 | 高重复负载极高 | RAG / 代码补全 / 抽取 |
| self-drafting | 跳过目标模型部分层(layer skip)/ look-ahead | 否 | 中 | 单模型部署 |

关键洞察:

1. **α 取决于"draft 分布与目标有多近"** → EAGLE(特征级)≥ Medusa(同模型头)> 小模型(家族匹配度决定)
2. **n-gram 是黑马**:负载自重复高时(RAG 答案引用原文、代码模式),候选就在上下文里,α 可逼近 1 且 draft 成本 ≈ 0
3. **tree attention**:draft 分叉成树(每位置多候选),接受率提升;验证成本 = 树节点数。γ 与树宽的乘积才是真实验证成本(vLLM/SGLang 均支持)

## 7.3 工程实现

- vLLM:`--speculative-model <draft>`(小模型),或 EAGLE 配置(`speculative_config` method=eagle)
- SGLang:`--speculative-algorithm EAGLE --speculative-num-steps γ --speculative-eagletopk k`
- 源码点(vLLM `vllm/v1/spec_decode/`):draft 批量 forward(γ 步)→ tree mask 构建(哪个位置可验证哪些候选)→ 目标验证 forward(每请求 γ+1 个位置,一次 forward)→ 7.1 的采样 → 请求状态按"接受长度"推进
- **α 监控**:框架逐 step 记录接受率 → α 是运行时可调变量:α < 0.5 → 降 γ 或对该请求关闭(按请求自适应)

## 7.4 什么时候不 work(经验表)

1. **高 batch**:GPU 已打满(Ch1:AI 高、compute-bound)→ 并行验证 γ token 不比 γ 个串行步便宜——投机只在"decode memory-bound、低 batch"区域有效
   经验:7B-70B 单机,batch < ~32 有意义;batch 128+ 常净亏
2. **低 α**:代码 / 数学 / 长尾词 → γ 被浪费
3. **短输出**:输出 < 2γ 时摊不平 draft 开销
4. **长 prompt 短输出**:TTFT 被 prefill 主导,投机只帮 decode

经验曲线(示意,7B、γ=5):batch=1 → 3×;batch=16 → 1.6×;batch=64 → 1.05×;代码负载(α≈0.4)→ 从 1.4× 掉到 0.9×(负收益)。

> **面试陷阱框:"投机解码总是更快,对吗?"**
> 答:三个条件缺一不可——(a) decode 处于 memory-bound 区(低 batch);(b) α 足够高(draft 接近目标);(c) 输出足够长。生产里把 α 当被监控指标,把投机解码当**可开关特性**而不是默认配置。
