## 8.1 数值格式

| 格式 | 符号/指数/尾数 | 动态范围 | 相对精度 | 主要用途 |
|---|---|---|---|---|
| FP16 | 1/5/10 | ±65504 | 高(10 位) | 推理权重(小模型) |
| BF16 | 1/8/7 | ±3.4×10³⁸(同 FP32) | 低(7 位) | 训练/推理默认 |
| FP8 E4M3 | 1/4/3 | ±448 | 中 | 前向(权重+激活) |
| FP8 E5M2 | 1/5/2 | ±57344 | 低 | 梯度(范围优先) |
| NVFP4 | E2M1 + FP8 block scale | 极小 | 粗 | B200 权重/激活(Blackwell) |
| MXFP4 | E2M1 + E8M0 scale(32 元素组) | 小 | 粗 | 同上(标准 OCP 格式) |
| INT8 | 8 位整 | ±127 | 线性 | W8A8 |
| INT4 | 4 位整 | ±7 | 粗 | W4A16(per-group scale 必须) |

要点:

- **量化 ≠ 单纯减 bit**,是"值 → scale × 码字"。误差两大来源:**范围裁剪**(outlier 超出动态范围)+ **台阶舍入**(精度不足)
- FP8 的 E4M3/E5M2 分工:前向用 E4M3(精度优先,范围够用),梯度用 E5M2(范围优先)——同一个 "FP8" 名字下两种格式

**H100 FP8 为何 2×(面试必须两步答)**:

1. **指令级**:H100 tensor core 的 FP8 MMA 指令吞吐是 FP16 的 2×(同一流水线,每 lane 多处理一个元素)
2. **Roofline 级(Ch1 §1.5)**:decode memory-bound → 权重字节减半,直接 ~2× 带宽收益;prefill compute-bound → 吃满指令级 2×
   **两条路叠加,FP8 在 decode 上收益最大**——这正是"量化主要服务 decode"的定量根据。
3. B200:NVFP4 tensor core 再 ×2(FP4 dense ≈ 2× FP8),MoE 与 decode 受益最大

## 8.2 后训练量化(PTQ):三个流派

**GPTQ(二阶误差补偿)**:逐层做 Hessian(激活二阶统计),按列量化、把舍入误差"加到"未量化列上补偿。质量稳、校准慢(每层 Hessian)。

**AWQ(激活感知)**:观察 ~1% 的 **salient channels**(激活幅度大的通道)贡献了大部分误差;对这些通道做 per-channel scale 保护,再整体量化。无 Hessian,快,工程上最常用。

**SmoothQuant(难度迁移,W8A8 的前提)**:W8A8 的难点是**激活 outlier**(权重量化容易,激活难)。按通道乘除一个因子 s:Y = (X/s)·(s·W) —— 数学等价,把激活的动态范围难点"迁移"一部分到权重侧,两边都变得可量化。

**weight-only W4A16 / W4A8**:

- 权重 INT4/FP4(per-group scale,group 通常 64/128),激活 FP16(或 FP8)
- kernel:GEMV/GEMM 内融合 dequant(或 LUT-GEMV:查表代替乘)
- 收益:H100 decode 权重字节 ↓2-4× → 带宽收益(Ch1 roofline);prefill 收益小(compute-bound)
- 代价:dequant 开销、精度损失(4bit 台阶粗)

**校准集**:128-512 条**真实任务分布**样本。校准集错了 = 量化白做:out-of-domain 样本 → Hessian/scale 估计偏差 → 误差在真实流量上放大。

## 8.3 W8A8 / FP8 推理路径

- **FP8 GEMM**:权重 FP8 + 激活 FP8 → FP8 tensor core;**per-token / per-block 动态 scale**(DeepGEMM:JIT + TMA multicast,配合 TP,Ch12)
- **TransformerEngine**:PyTorch 侧 FP8 autocast 封装,自动维护 scale / amax 历史(动态量化需要"先估计范围再量化",amax 用滑动统计)
- **KV FP8**:Ch5 §5.5.1(显存减半、并发 ×2、近无损)
- 经验精度序(7B+ 模型,可复测):**FP8 W8A8 ≈ 近无损 > INT8 W8A8(SmoothQuant) > W4A16(小损,任务相关)> W4A8/FP4(需 B200 + 精校准)**

## 8.4 精度评估方法(PPL 不够)

1. **perplexity**(wikitext/c4):粗筛。PPL +0.1 可能已经打坏下游任务——PPL 是语料平均,看不见长尾
2. **任务 benchmark**:生产任务集(chat / 代码 / RAG / 结构化输出),样本 ≥ 100,对比 BF16 基线的 Δ
3. **长上下文退化**:量化误差随序列累积,8K / 32K 各测一组
4. **few-shot / 指令遵循**:结构化输出格式错误率是敏感指标
5. **MoE 特化**:router(小矩阵、指数敏感)与 shared expert 常保高精度;routed expert 可激进
6. **报告模板**:模型 / 位宽 / 校准集 / 各任务 Δ / 长上下文 Δ / 延迟-吞吐变化(接 Ch2 口径)

> **案例框(合成)"PPL 只涨 0.05,为什么代码任务掉了 3 个点?"**
> 代码 token 长尾(罕见符号/标识符)的量化误差大,而 PPL 在通用语料上平均,完全看不到。教训:**在自己的目标任务上评估,不在 PPL 上评估**。

## 8.5 [进阶]

- **MoE 量化**:per-expert per-group scale;热 expert 保高精度、冷 expert 激进(流量分布决定精度分配,接 Ch16 热 expert)
- **QAT**:PTQ 不够时(小模型、极端位宽)用训练期伪量化;成本是训练流水线,生产团队少用
- **动态量化**:FP8 推理基本用动态 scale(per-token/per-block,运行时 amax),静态 scale 只用于权重
- **B200 + NVFP4**:DeepSeek 系生产部署实践;成本模型:权重字节 1/4 → 单卡模型容量 ×4,decode 带宽 ×4(理想),prefill 吃 FP4 tensor core
- **量化 × 投机解码**:draft 模型可以更激进量化——rejection 采样保证输出仍无损(Ch7),但 draft 分布偏离变大 → **α 下降**,要实测加速比
