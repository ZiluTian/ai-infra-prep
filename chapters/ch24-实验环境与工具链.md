## 24.1 单卡环境(最低 1×A100 40G / 1×4090 24G)

**版本矩阵(2026-11 基线,权威核对见附录 G §G.1)**:

```
驱动 ≥ 550(CUDA 12.4+)    PyTorch ≥ 2.4(CUDA 12.4)
vLLM v0.32.x(V1 引擎, pip wheel)   SGLang v0.5.x
ncu/nsys: Nsight 2025.x   DCGM: datacenter-gpu-manager
```

**步骤与验证**:

```bash
# ① 驱动与 GPU
nvidia-smi                       # 期望:驱动版本、显存、topology 正常;4090 看 NVLink 列(应为空)
nvidia-smi topo -m               # A100 两卡:NV#;4090 多卡:SYS/PIX(TP 天花板,Ch18 §18.1)

# ② 容器(推荐官方镜像,版本矩阵自洽)
docker run -it --gpus all --cap-add=SYS_ADMIN \
  -v ~/labs:/labs nvcr.io/nvidia/pytorch:24.xx-py3 bash
# SYS_ADMIN:ncu 需要;--gpus all:容器内可见全部 GPU

# ③ 框架安装与冒烟
pip install vllm                  # 或 pip install "sglang[all]"
python -c "import vllm; print(vllm.__version__)"
vllm serve Qwen/Qwen2.5-7B-Instruct --gpu-memory-utilization 0.9 \
     --port 8000 &                # 4090 24GB:7B FP16 勉强(权重 14GB,KV 池 ~8GB);14B 起需 --quantization fp8
curl -s localhost:8000/v1/chat/completions -d '{"model":"Qwen2.5-7B-Instruct",
  "messages":[{"role":"user","content":"ping"}],"max_tokens":16}' | head -c 300
# 期望:流式返回;TTFT 量级:7B 单卡 ~50-200ms(冷)
```

**4090 的实验边界(必须写进实验报告)**:

- **无 NVLink** → TP > 2 不可用(PCIe 通信,Ch18);一切多卡实验结论**不可外推**到 NVLink 环境
- **功耗墙 400W + 动态降频** → 持续压测性能随温度漂移;结果标注"4090,持续负载 N min"
- **24GB 上限** → 7B FP16 权重 14GB + KV 池只剩 ~8GB(并发上限低,Ch3 公式验证);"70B 实验"只能跑量化 + 小 batch,或改用 A100/H100
- **结论外推规则**:单卡算子/量化结论可参考,**并行/通信结论一律标"不适用"**

## 24.2 源码环境(vLLM v1 开发)

```bash
git clone --depth 1 https://github.com/vllm-project/vllm && cd vllm
pip install -e .                 # 会编译 C 扩展(需要 nvcc;~10-30min)
export VLLM_LOGGING_LEVEL=DEBUG  # 或 --log-level debug
```

**关键断点位置(与 Ch4 代码地图对应;用日志断点而非交互 debugger)**:

| 位置(文件.方法) | 看什么 |
|---|---|
| `vllm/v1/core/sched/scheduler.py` → `schedule()` | 每步的 batch 构成、token 预算分配、抢占决策(Ch6) |
| `vllm/v1/worker/gpu_model_runner.py` → execute 主循环 | 每步输入组装(block table 更新)、graph 选择(Ch12) |
| `vllm/v1/attention/backends/` | paged attention 的元数据构建(Ch5) |
| `vllm/v1/spec_decode/`(若开投机) | draft/verify 状态、接受长度(Ch7) |

方法:在目标方法开头 `logger.info(...)` 打时间戳 + 关键变量,重定向到文件后离线分析——**生产代码不要挂 pdb**(双进程模型下会卡死调度,Ch4 §4.4)。

## 24.3 工具链

**nsys / ncu(Ch10 §10.4 的完整命令)**:

```bash
# nsys: 服务冒烟抓 60s(稳态负载下)
nsys profile --trace=cuda,nvtx -o /tmp/run --duration 60 -- python my_infer.py
# 对已运行进程(交互法,跨版本稳定):nsys launch <options> <app> 之后 nsys start --duration 60,完事 nsys stop
# (2025.5 以前的 nsys 也可直接 nsys profile --attach-pid=<pid>;新版该旗标已移除)
# ncu: 单 kernel 深钻(容器需 CAP_SYS_ADMIN)
ncu --set full -k "regex:.*gemm.*" -c 3 python my_infer.py
# 权限验证:跑 1 个 kernel 不报 "Permission denied" 即 OK
```

**nccl-tests(通信基线,Ch18)**:

```bash
git clone https://github.com/NVIDIA/nccl-tests && cd nccl-tests
make MPI=1 -j && ./build/all_reduce_perf -b 8M -e 8G -f 2 -g 8
# 单卡/单节点直接跑;多机加 mpirun(§24.4)
# 判读:busbw 列,节点内期望 ~780GB/s(NVLink,Ch18 §18.4)
```

**GenAI-Perf(NVIDIA 官方 LLM 压测器,Ch2 模板的替代)**:

```bash
genai-perf profile --model Qwen/Qwen2.5-7B-Instruct \
  --endpoint-type chat --request-rate 8 --duration 120 \
  --service-host 127.0.0.1 --service-port 8000
# 输出:TTFT/TPOT/ITL 分位 + 吞吐,与 labs/bench_basics.py 口径互验
```

**DCGM exporter + Prometheus + Grafana(Ch23 看板的地基)**:

```bash
docker run -d --name dcgm --gpus all --network host nvcr.io/nvidia/k8s/dcgm-exporter:3.x

```

## 24.4 多机环境(可选,实验二/三需要;2 节点起步)

**RDMA 验证三连(每节点跑,全部通过才配谈 EP/P-D)**:

```bash
ibstat                          # 期望:State: Active, PhysicalState: LinkUp, MTU: 4096(1024 = 降速,Ch18 §18.4)
rping -s &  rping -c <对端IP>   # 期望:延迟 ~2-5μs,带宽接近线速(单口 50GB/s 量级)
# GDR 检查:nccl-tests 跨机 busbw ≈ 0.875 × 链路带宽 × NIC 数;只有 ~50% → GDR 失效(Ch18 排障 2)
```

**节点间 MPI(OpenMPI)**:SSH 免密 + `/etc/hosts` 互通 + 防火墙放行(或 `--mca btl_vader_single_copy_mbox_threshold`)。

**NCCL 基线(存档,后续实验的对照基准)**:

```bash
# 节点内(8 卡)
mpirun -np 8 ./build/all_reduce_perf -b 8M -e 8G -f 2 -g 1
# 跨机(2 节点 × 8 卡)
mpirun -np 16 -H node1:8,node2:8 -x NCCL_SOCKET_IFNAME=eth0 \
  -x NCCL_IB_HCA=mlx5 ./build/all_reduce_perf -b 8M -e 8G -f 2 -g 1
# 存档:results/env-baseline/nccl-<date>.csv(节点内/跨机各一份)
```

**常见失败模式**(多机环境 90% 的坑在这一步暴露):hostname 解析失败、NCCL bootstrap 选错网卡(多网卡机器必设 `NCCL_SOCKET_IFNAME`)、MTU 不一致、PFC 未配(RoCE)。

> **踩坑框:"环境没问题,实验才有意义"**
> 三个最常见的"假结果"来源:① 驱动/CUDA 与框架不匹配(静默降级路径,性能 30% 损失无报错);② 压测负载不对(全短请求测长上下文结论);③ 空载没存档(调优后无法证明"相对基线")。**checklist 不全 → 实验作废重来**,这是本部分唯一的硬性规定。
