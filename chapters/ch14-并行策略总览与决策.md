## 14.1 每种策略一张卡片

| 策略 | 切什么 | 通信模式 | 延迟特性 | 故障域 | 主要用途 |
|---|---|---|---|---|---|
| **TP** | 层内权重(列/行切) | 每层 2 次 all-reduce(或 all-gather + reduce-scatter) | 低延迟、高频 → **限节点内 NVLink** | 单节点 | 稠密大模型节点内切分 |
| **PP** | 层间(前 N 层 / 后 M 层) | 点对点 send/recv(激活前向) | 小消息 × 少次;有 **bubble**(流水线空转:下游 stage 等上游激活到达,Ch17 §17.1)、怕 straggler | 可跨机 | 跨机稠密大模型、MoE |
| **DP** | 整模型复制 | 推理期**副本间零通信**(KV 独立) | 各副本独立 | 单副本 | 过载削峰、小模型扩容 |
| **EP** | MoE expert 分布 | all-to-all ×2/层(dispatch + combine) | decode 延迟主导、prefill 带宽主导 | EP 组 | MoE(Ch13/16) |
| **SP** | 序列维激活(层内) | all-to-all(Ulysses)或 P2P(ring) | 随序列长增长 | TP 组内 | 长上下文 / 训练(Megatron) |
| **CP** | 序列维 attention(ring) | KV 环状 P2P 轮转 | 长 prefill 专用 | CP 组 | 1M 上下文 prefill(Ch17) |

一句话记忆:**TP 切权重(每层都通信)、PP 切层(只在边界通信)、DP 不切(零通信)、EP 切 expert(每层两次 all-to-all)、SP/CP 切序列(通信随 N 涨)**。

> **集合通信四件套速查**(Ch15/18 详解):**all-reduce** = 各 rank 发自己的值,求和后每个 rank 都拿到和(TP 层内,Ch15);**all-gather** = 各 rank 发自己的分片,每个 rank 拿到完整数据(序列并行,Ch15 §15.2);**reduce-scatter** = all-gather 的"反向":求和后每个 rank 只拿属于自己的一段(Ch15 §15.2);**all-to-all** = 每个 rank 给每个对端发不同的分片(MoE dispatch/combine,Ch13)。一句话:all-reduce"人人拿到和"、all-gather"人人拿到全部"、reduce-scatter"人人拿到和里自己那段"、all-to-all"洗牌"。

## 14.2 通信量公式(本章定量核心)

**TP all-reduce**(每层 2 次:attention 输出投影后 + MLP 下投影后;Ch15 详述):

```
(14-1) 单次 all-reduce 消息 ≈ bs × seq × hidden × bytes
       每步总量 ≈ layers × 2 × 该消息
```

手算(70B,hidden 8192,decode bs=1,FP16):单次 = 8192 × 2B = **16 KB**;每步 = 80 层 × 2 × 16KB = **2.5 MB**。
- NVLink(900GB/s,ring 算法系数 ~2(N-1)/N ≈ 1.75):纯传输 ≈ 2.5MB ÷ (0.9×900GB/s) ≈ 3μs,加小消息延迟地板 → **每步 ~50-100μs 量级**(TP8,实测依拓扑)
- (2(N-1)/N 系数来源:ring all-reduce = N−1 个 reduce 阶段 + N−1 个 gather 阶段,每阶段消息 = 总量/N,每 rank 总收发 ≈ 2×(N−1)/N × 总量 → 大消息下 nccl-tests 的 busbw 趋近 2(N−1)/N × 链路带宽,判读必须用 busbw 而非 algbw,Ch18 §18.4)
- 跨机 IB(50GB/s):×18 → **每步 1-2ms 量级**——decode step 若只有 ~5ms,通信占 20-40% → **"TP 不宜跨机、TP ≤ NVLink 域(≤8)"的定量根据**

**EP all-to-all**(Ch13 (13-1)):

```
总发送 ≈ batch × seq × topk × hidden × bytes;每对链路 ≈ 总量 / (N−1)
```

手算:671B MoE、EP8、decode batch 64、top-8、hidden 7168、FP16 → 每层 7.3MB(Ch13),对 IB 是延迟主导、对节点内 NVLink 是几十 μs 量级。

**PP 点对点**(每过一个阶段边界一次;单请求 decode):

```
(14-2) 每边界 ≈ micro_bs × hidden × bytes;每步 ≈ (stages−1) × 该消息
```

手算:PP8、hidden 8192、bs=1 → 7 × 16KB = **112 KB/步**——量很小,但**串行 7 跳延迟**(每跳 μs 级)+ 单请求时的 bubble(Ch17):PP 的代价不是带宽,是**跳数延迟与 straggler 放大**。

```
bubble 小图(PP2、单请求):
  stage1: [ 计算 ────── ][ 等待 ············ ]
  stage2: [ 等待 ············ ][ 计算 ────── ]
           ↑ 空转 = bubble;micro-batch 切细后各 stage 的计算/等待错峰,
             bubble 占比 ≈ (stages−1)/micro_bs(Ch17 §17.1)
```

**汇总口诀**:

- TP:小消息 × 每层 2 次 × 低延迟要求 → 只能 NVLink
- EP:消息随 batch 变,decode 延迟主导、prefill 带宽主导
- PP:小消息 × 少次 × 跨机可承受 → 代价在跳数与 bubble
- DP:推理期零通信 → 扩容最便宜

## 14.3 决策框架(决策树)

```
Q1: 单节点装得下吗?(Ch3 容量公式,先算 KV 余量)
├─ 装得下(稠密) → TP ≤ 8(NVLink 域内);多副本 DP 扩容量
│  装得下(MoE)  → 节点内 EP(×TP,见 Ch16)
└─ 装不下(跨机)
   ├─ MoE → EP 为主(expert 天然可切,通信可承受)+ attention 侧 TP(EP×TP 混合)
   ├─ 稠密 → PP(跨机,付 bubble)或 跨机 TP(极不推荐,14.2 的 ×18)
   └─ 装得下但过载 → 先 DP 加副本(零通信),再加卡
Q2: 上下文 100K+?
└─ prefill:CP / SP(切序列);decode:KV 随 TP/CP 分布(Ch17)
   典型形态:P/D 分离(Ch9),prefill 集群 CP,decode 集群 TP
Q3: 多 SLO / 过载?
└─ 多池 DP + 请求路由(Ch19);必要时 P/D(Ch9)
```

**三个工作例(面试标准答案)**:

1. **70B 稠密、8K 上下文、高并发 chat** → 单节点 **TP8**,FP8 KV 抬并发(Ch3/5),**DP 多副本**扩容;P/D 暂不需要(短上下文,Ch9 判据)
2. **671B MoE(V3/R1)、128K 上下文、高并发** → **DP × (attention TP8 + expert EP 跨节点)**:节点内 NVLink 做 attention TP 与 intra-node dispatch,跨节点 RDMA 做 expert EP(Ch16 §16.4 生产形态)
3. **1M 上下文 prefill 主导(长文档 RAG)** → **prefill-only CP 集群**(Ch17:CP8-16,prefill 切序列)+ decode TP8 池 + P/D 分离(Ch9 案例)

## 14.4 [进阶] 多维并行与 gang 调度

**多维并行的层级关系(必须说清"谁包谁")**:

```
DP(副本级,零通信)
 └─ 副本内:
     ├─ attention: TP(节点内 NVLink)
     ├─ expert:   EP(可跨节点 RDMA)
     └─ 长 prefill: CP(序列维,可跨节点)
```

关键约束:**TP 必须落在 NVLink 域内(≤8)**;EP 可以跨节点(all-to-all 走 RDMA);CP 跨节点时 KV 轮转走 P2P(RDMA);三者通信域不同,排布时**节点是基本单元**——一个节点内塞满 TP 域,节点间才谈 EP/CP/DP。DeepSeek 系生产形态就是"节点内 TP8(attention)+ EP(跨节点 expert)+ DP(多副本)"。

**gang 调度(K8s + Volcano)**:

- 一个并行组(TP8 = 1 节点 8 卡;EP64 = 8 节点)必须**整组分配**,partial 分配无意义——TP8 少一张卡,整个组不可用
- **故障域**:节点挂 = 整个并行组挂(TP/EP/CP 状态都跨卡)。DP 数 = 副本数,挂 1 节点丢 1 副本容量;生产决策必须含"挂 1 节点后的剩余容量 vs SLO"(Ch23/Ch29 案例 9)
- 抢占与混部:gang 组整体抢占、整体归还(Ch19 §19.4);训练/推理混部时,推理 gang 组通常**不可被训练抢占**(SLO 优先级)
