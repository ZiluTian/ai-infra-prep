# 第 30 章 简历与项目表达

> ~10 页 | 前置:Ch25-27(实验交付物即素材)、Ch28-29(题库与案例即弹药)
> 目标:把 Ch25-27 的实验产物 + 前六 Part 的知识,变成**可被追问、可被验证、可被复述**的面试材料。
> 本章不是"话术合集"——话术背不出深度。它给的是**结构**:STAR 骨架、数据口径、红旗自检、模拟流程、反问清单。

## 30.1 推理优化项目怎么写进简历

### STAR + 量化的骨架

一段"可面试"的项目描述 = **S/T(1 句)→ A(2-3 句,机制级)→ R(2-3 句,数字级)**:

- **S/T**:什么负载、什么硬件、什么 SLO(1 句,给面试官坐标系)。
- **A**:你做了什么**机制级**的动作(不是"优化了性能",是"用 nsys 定位 launch-bound → token 预算 2K→8K + chunked prefill + 前缀路由")。
- **R**:数字 + **口径**("p95 TTFT −45%,真实负载画像压测,Ch2 口径")。

### 量化指标词表(从中选 3-5 个,别堆)

| 类别 | 指标 | 例子 |
|---|---|---|
| 延迟 | TTFT/TPOT p95/p99 变化 | p95 TTFT −45%(8K 桶) |
| 吞吐 | goodput / 吞吐变化、$/M token | goodput +90%;$/M token −38% |
| 容量 | 并发、KV 使用率、卡数 | 同卡数并发 32→110;或 需求不变省 N 卡 |
| 稳定性 | p99/p50 比值、抢占计数、故障 MTTR | p99/p50 3.1→1.6;夜间抢占 0 |
| 成本 | 利用率、峰谷 | 集群利用率 41%→68%(SM Active 口径) |

**每个数字必须能跟一句"怎么测的"**(Ch2 的测量口径:负载画像 + 分位 + 分桶 + 硬件/版本快照)。面试官听到数字的第一反应是"可复现吗"——口径句就是答案。

### 范本(基于 Ch25 实验一,数字为示意 [假设],替换为你自己的实测)

> **70B 稠密模型生产部署与性能调优**(S: 高并发 chat 服务,H100 × 8 节点,SLO p95 TTFT 2s / p99 TPOT 100ms)
> - 用 nsys/ncu 三层定位(Ch20 L1→L3)发现吞吐瓶颈 = 小 batch + CPU launch gap;token 预算 2K→8K、开 chunked prefill、前缀感知路由,压测用真实负载画像(长短 8:2 + 前缀 50%)。
> - 结果:p95 TTFT −45%、p99 TPOT −28%、goodput +90%;$/M token −38%(Ch2 口径,同硬件同负载 A/B)。
> - 上线配套:性能回归 CI(nightly bench,5% 门禁)+ 灰度 5%→100%(Ch23 §23.4)。

三行的信息密度:第一行给坐标,第二行给**机制 + 方法**,第三行给**数字 + 口径 + 工程闭环**。任何一行被追问都能展开成 Ch25/Ch20/Ch23 的内容。

### 难度分级(写之前先定档)

- **中级(3-5 年)**:1-2 个项目,每个覆盖"部署 → 画像 → 调参 → 压测 → 上线"闭环;强调**方法完整性**(Ch20 三层、Ch2 口径)而非规模。
- **高级(5 年+)**:至少 1 个**架构级**项目(P/D、EP 多机、容量规划)+ 1 个**成本闭环**(案例 4/10 的口径)+ 1 次**重大事故主导**(案例 9 的语义)。强调**权衡与决策**(为什么选 X 不选 Y,代价是什么)。

## 30.2 源码级经验怎么讲

### 反模式 vs 正确模式

| 反模式(零信息量) | 正确模式(三段:改了什么 / 在哪定位的 / 拿到什么数据) |
|---|---|
| "我读过 vLLM 源码" | "nsys 看到 decode 步 2ms gap,先验证 CUDA graph 是否生效(分桶 + block table 间接,Ch12 §12.3),确认逃逸在采样 kernel;ncu 看 Memory SOL 65% 后做了融合,kernel 数 400→180,gap 降到 0.4ms" |
| "我懂调度器" | "token 预算是 goodput 核心旋钮(Ch28 B14);我按 Ch25 §25.4 方法对 2K/4K/8K/16K 做了 A/B 扫描,得到 p99/吞吐交换曲线,生产值按 SLO 拐点定" |
| "我了解 MoE" | "Ch16 实验 16.1 的偏斜注入(测试 hook 强制 top-8 集中)复现了 p99 ×4;静态放置热 expert 后 p99 回落 30%,与 Ch13 §13.4 的量化一致" |

### 三个层级,简历里必须可区分

1. **用过**(部署/配置/调参)→ 可讲:参数选择理由 + 压测数据。
2. **剖析过**(nsys/ncu/DCGM 定位到机制)→ 可讲:证据链(L1→L2→L3,Ch20)。
3. **改过**(kernel/调度器/框架的内网改动或 PR)→ 可讲:改动动机 + 对照实验 + 回归(Ch23 §23.4)。

**没有第 3 层不丢人,但绝不能把第 1 层说成第 3 层**——面试官用"具体改的哪个文件、哪个方法、diff 大概长什么样"(全书源码引用就是 文件+方法 级的口径)三问即知。

### 没改过源码,怎么讲"源码级理解"

讲"**读过的代码路径 + 验证它的实验**":如"我读过 vLLM v1 调度器的 token 预算分配路径(文件+方法级),并用实验 6.1 的模拟器复现了其调度行为,与引擎指标吻合"。**理解 = 能预测行为 + 有实验佐证**,这是可展示的,不需要 commit 记录。

## 30.3 常见简历红旗与修正

| 红旗 | 为什么减分 | 修正 |
|---|---|---|
| 只有"部署过 vLLM/SGLang" | 部署是起点不是成果;"部署后做了什么"答不出 = 操作工 | 补调优闭环:画像 → 定位 → 调参 → 数据(30.1 范本) |
| 无数据 / "显著优化" | 无法验证,且暴露没有压测纪律 | 任何"显著"换成分位数字 + 口径(Ch2) |
| 无权衡("开 FP8 就快了") | 不知道代价 = 没真正做过;FP8 有质量门禁/长上下文退化/生态成本 | 句式固定为:"做了 X,代价是 Y,用 Z 验证了可接受" |
| 指标不可复现(裸数字) | 面试官会问"什么负载、什么硬件、什么版本" | 数字后跟三件套:负载画像 + 硬件快照 + 模型/引擎版本(Ch2 可复现性要求) |
| 术语堆叠(Roofline、WGMMA、all-to-all 无上下文) | 背概念 vs 用概念,一问即穿 | 每个术语绑一个具体使用场景("Roofline 用来判定 decode 是 memory-bound,指导我选 W4A16 而不是堆卡") |
| 角色夸大(全团队 = 我) | 追问"你具体负责哪部分"会崩 | "我负责 X,团队做了 Y,其中 Z 是我的设计"——边界清晰反而加分 |
| 纯运维无剖析 | 5 年+ 岗位要"性能判断力",不只是"会操作" | 至少一个完整的 L1→L2→L3 定位链(Ch20)+ 一个"反直觉"结论(如"GPU util 低但吞吐差,根因是 CPU 调度") |
| 只有成功没有失败 | 真实工程必有 detour;全成功 = 不可信 | 准备一个"走过的弯路"(30.4 要求带一个失败案例进面试) |

**自检方法**:把简历给一个没参与的人读 3 分钟,让他列出"最想追问的 3 个数字/3 个术语"——你答不全的,就是红旗。

## 30.4 模拟面试流程

> 标准四段(总 ~2.5-3h):30min 自我介绍与项目概览 → 60min 项目 deep-dive → 45min 系统设计(Ch29 抽题)→ 45min 白板/编码。

### ① 自我介绍(30min 段里实际讲 3-5min)

- **3-5min 版**(必背但别背出背诵感):一句话定位("X 年推理 serving,最擅长性能定位与容量规划")→ 两个项目各 3 行(30.1 骨架压缩)→ 一句想强调的("最近在做 P/D 分离的容量规划,案例 10 的完整链路")。
- **15min 版**:每个项目展开"一个最有代表性的定位过程"(Ch20 五段式:现象 → 假设 → 证据 → 结论 → 回归)。
- 原则:**说深的一点点透,胜过说宽的样样点到**——深度展示 30.2 的层级,广度靠后续追问自然展开。

### ② 项目 deep-dive(60min)

- **骨架 = Ch27 §27.6 报告模板**:背景/负载 → 架构 → 调优过程(**3-4 次迭代,每次"假设 → 证据 → 结论"**→ 最终数据 → 权衡与代价 → "如果重来会不同"。
- **面试官的追问顺序(按此准备)**:"为什么选 X(不选 Y)"→ "如果 X 不 work 你试过什么"→ "怎么测的"→ "代价是什么"→ "上线后出过什么问题"。
- **必须带一个失败案例**("最大的 detour"):如"chunk 开 16K 以为 TTFT 更好,p99 反而 ×2——长 prefill 占步,Ch28 B23 的反直觉;后来回 8K 并用 P/D 立项"。失败案例 + 正确归因 = 高级信号。
- 数据新鲜度:**面试前 30 天内重跑过 bench**(脚本在 labs/ 与 Ch24 环境),被问"最近一次压测是什么时候"答得出日期。

### ③ 系统设计(45min,Ch29 抽题)

- 高频:案例 1 / 5 / 10(综合度最高);案例 2 / 8 常作追问分支。
- 节奏(Ch29 章首):5min 澄清 + 10min 算账 + 15min 架构 + 5min 留追问。**算账段必须出声套 Ch3 公式**——静默心算 = 面试官无法验证你的方法。

### ④ 白板/编码(45min)

三选一,按岗位调整(问清"想看哪类"):

1. **Triton kernel**:fused RMSNorm(Ch12 §12.1 Step 1)或 paged decode attention 骨架(Ch11 §11.6)。**正确性优先**(与 torch 参照对比),性能第二(讲清 tile 选择与 online softmax 状态)。
2. **调度器模拟器**(Python ~100 行,Ch6):waiting/running 队列 + token 预算 + 抢占 + chunked prefill;输出 TTFT/TPOT 随负载的曲线;能回答"预算从 2K 加到 8K,曲线怎么变"。
3. **容量计算器**(labs/capacity_planner.py 骨架,现场推导 Ch3 公式链):输入流量 → 输出卡数;能现场改一个参数(前缀命中率)看结果变化。

### 面试前 24h 清单

- [ ] 简历里每个数字能脱口而出"怎么测的"(30.3 自检)
- [ ] Ch28:3 分钟版抽 20 题自测(A/B/E 各若干,遮住答案说)
- [ ] Ch29:选 1 个案例按 40min 计时练一遍,对照 ◆ 评审点打钩
- [ ] 白板题:RMSNorm 的 Triton 伪代码默写一遍(或调度器模拟器的核心循环)
- [ ] 反问清单(30.5)按目标岗位挑 3 个

## 30.5 反问清单

> 技术轮末尾用,≤3 个,按重要性排序;薪酬福利留到 HR 轮。

| 问什么 | 它暴露什么 | 怎么反推岗位真实水平 |
|---|---|---|
| "现在线上 LLM 服务最大的 SLO 是什么?当前最大瓶颈在哪?" | 团队阶段:greenfield / 爬坡 / 救火 | 答"刚起步" = 建设型(方法完整者加分);答"p99 尖刺 / 容量紧" = 救火型(Ch20-23 技能直接对口);答"没有显式 SLO" = 成熟度偏低(要评估你是否要当那个建 SLO 的人) |
| "集群规模与硬件构成?" | 技术天花板 | 单机 7B/14B = 部署岗;多机 H100/H200 + MoE = 分布式岗(Ch13-19 弹药全用得上);B200 占比高 = 窗口期红利(Ch28 C26) |
| "推理引擎用什么?kernel 层谁维护?" | 岗位深度 | 纯 vLLM/SGLang 用户 = 引擎调优 + 容量;有自研 kernel 团队 = 可往 Ch11-13 深挖;两可 = 问"kernel 层和 serving 层的边界在哪" |
| "容量规划和成本核算怎么做的?有没有 $/M token 口径?" | 组织成熟度 | 有口径 + 租户归因 = 成熟(Ch19 §19.4/Ch23 §23.3);没有 = 你的机会(案例 10 是现成的提案) |
| "性能回归怎么做?CI 里有 nightly bench 吗?" | 工程纪律 | 有门禁 = 进组即产出;没有 = 你前 3 个月的活(既是工作也是卖点) |
| "训练和推理是否混部?" | 负载复杂度 | 混部集群 → 峰谷/隔离/抢占话题(Ch19 §19.4);纯推理 → 容量规划主线 |
| "模型族是什么?稠密 / MoE / 长上下文?" | 决定 Ch29 抽哪个案例 | 据此把 30.4 的演练重心移到对应案例(稠密 → 1/2/7;MoE → 1/8;长上下文 → 3/5) |
| "未来 6 个月最大的技术挑战?" | ≈ 岗位职责的真实描述 | 答"上 P/D" = 你会被考案例 5;答"成本降 50%" = 案例 4;答"671B 上线" = 案例 1 + 9 |
| "这个岗位的 scope 和成长路径?" | 5 年+ 必问 | 看 ownership 边界:是"负责一个池"还是"负责推理平台"——与前六 Part 的能力模型对表 |

**反推公式(心里用,不说出口)**:`岗位水平 ≈ SLO 成熟度 × 集群规模 × kernel 归属 × 成本治理`。四项里两项以上低于你的技能档 = 降级风险(简历与岗位错配,面试会显得"过度"——反过来,你的简历也应按反推结果**裁剪深度**:对救火型团队多讲 Ch20-23,对建设型团队多讲 Ch3/Ch14 的规划能力)。

**礼仪边界**:不问竞品/别家待遇;不追问团队人事(离职率可委婉问"团队稳定吗");每个反问后**停顿听完整答案再追半句**("P/D 的话,现在 P:D 配比是静态还是动态?")——追问半句 = 真在听,不是走完流程。

## 章末自测

1. 用 30.1 的骨架写你的项目段(STAR + 3 个数字,每个数字带口径句),按 30.3 的表逐行过一遍。
2. 选一条源码级经验,用"改了什么 / 在哪定位的 / 拿到什么数据"三段重写,并标注你的层级(用过/剖析过/改过)。
3. 写 3-5min 自我介绍并计时(超 5min 砍项目,不砍定位句)。
4. 带一个失败案例进模拟:用 Ch20 五段式讲它(现象 → 假设 → 证据 → 结论 → 回归),重点练"归因正确"而非"结果漂亮"。
5. Ch29 抽 1 案例,40min 计时,请人按该案例"预期追问"节发问。

## 面试钩子

- 本章是 Ch28-29 的"使用说明":题库(点)、案例(面)、项目表达(体)——**先点后面后体**(Ch28 使用建议第 5 条)。
